# Генератор матрицы по статистическим ограничениям

Отдельный прототип первичного исследования по рецензии к §3–4
[THEORY.md](../paper/THEORY.md). Он не импортирует и не меняет действующий
`bipartite_gen.py`. Все параметры включённого примера — `assumed`.

## Запуск

Из корня репозитория, Python 3 с NumPy и SciPy:

```bash
python3 -m unittest sim4.test_constrained_gen -v
python3 sim4/constrained_gen.py --config sim4/constrained_example.json --output work/constrained-demo
```

`matrix.csv`: целые прослушивания, **строки — артисты, столбцы — слушатели**.
`payouts.csv`: выплаты PR/UC, отношение, аудитория и взвешенные средние
каждого артиста при W=1; `nan` обозначает неопределённое значение для
артиста без прослушиваний.
`report.json`: конфигурация, версии библиотек, seed, SHA-256 канонических
байтов матрицы (`<i8`, C-order), невязки до/после, история, покомпонентная
приёмка и проверки PR/UC. Число итераций включает предложения, которые
оказались недопустимыми ещё до пересчёта цели.

Коды выхода: 0 — все цели и ограничения прошли; 1 — кандидат сохранён,
но не принят; 2 — некорректная конфигурация. Конечный каталог задаётся
явно. При повторном запуске в том же каталоге его `matrix.csv`, `payouts.csv` и
`report.json` заменяются. Исходный репозиторный пример не перезаписывается.

## Контракт конфигурации

См. [полный пример](constrained_example.json). Обязательны:

| Поле | Смысл |
|---|---|
| `artists`, `listeners` | положительные числа артистов и слушателей |
| `total_plays` | целый общий объём, не меньше `listeners`; ограничен точным диапазоном float64 |
| `period` | общий период и единицы наблюдения; демонстрационный период не следует называть годом |
| `seed` | неотрицательное целое |
| `iterations` | неотрицательный лимит предложений |
| `max_transfer` | максимальное целое число переносимых за шаг прослушиваний |
| `temperature_start`, `temperature_end` | положительные температуры; для охлаждения конечная меньше начальной |
| `targets` | непустой список статистических целей |
| `listener_totals` | необязательно: положительные суммы всех столбцов, в сумме `total_plays` |

У каждой цели — уникальный `id`, `metric`, положительные `tolerance` и
`weight`, `status` из `measured / assumed / derived`, непустой `source`.
Статус задаёт автор эксперимента: программа не удостоверяет источник.
Параметры, сетки, веса и допуски фиксируют **до** запуска.

Для распределения задаются возрастающая конечная `grid` и `distribution`:

| `family` | Параметры | Исходная поддержка |
|---|---|---|
| `normal` | `mu`, `sigma > 0` | вся ось |
| `lognormal` | `mu`, `sigma > 0` для логарифма | положительные числа |
| `pareto` | `shape > 0`, `scale > 0` | x ≥ scale; CDF = 1−(scale/x)^shape |
| `beta` | `alpha > 0`, `beta > 0` | [0,1] |

Опциональные `lower`, `upper` задают усечение исходного закона;
`ceil: true` затем округляет случайное значение вверх. Например, для
числа артистов у слушателя закон normal следует усечь на (0,N] и
округлить вверх. Один целый порог x соответствует исходной CDF в floor(x).

Вычисляется `max(abs(observed_cdf - target_cdf))` **только на grid**.
Каждая CDF использует `≤`, в том числе при совпадающих целых значениях.
Это заданная мера подгонки, не p-value и не полный KS-супремум.

## Метрики и агрегация

Десять метрик принимают распределение:

- `listener_totals`: суммы столбцов P_u, все слушатели.
- `artist_totals`: суммы строк P_i, включая нули.
- `listener_degrees`: ненулевые ячейки столбца K_u.
- `artist_audiences`: ненулевые ячейки строки A_i, включая нули.
- `positive_plays`: все положительные ячейки, одна пара — одно наблюдение.
- `artist_weights`: положительные p_iu/P_i всех активных пар; артисты с
  большей аудиторией дают больше наблюдений. Это объединённое
  распределение, не одинаковая CDF для каждого артиста.
- `artist_weight_hhi`: сумма квадратов p_iu/P_i, по активным артистам.
- `listener_share_hhi`: сумма квадратов p_iu/P_u, по слушателям.
- `weighted_intensity`: m_i = Σ_u(p_iu/P_i)P_u, по активным артистам.
- `harmonic_intensity`: H_i = 1/Σ_u(p_iu/P_i)/P_u, по активным артистам.

Четыре скалярные метрики принимают `value`:

- `zero_fraction`: доля нулевых ячеек во всей матрице.
- `artist_top_share`: доля общего объёма у верхних ceil(fraction × N)
  артистов по сумме строки; требуется `fraction` из (0,1].
- `artist_gini`: Джини сумм строк, включая нули, без поправки N/(N−1).
- `activity_audience_correlation`: Pearson corr(log A_i, log(P_i/A_i))
  по активным артистам. Постоянная переменная или меньше двух артистов
  дают `null` и FAIL, даже при широком допуске. Это не регрессионный наклон emp1.

Пустые артисты получают PR=UC=0; отношение и их средние не определены.
В объекте выплат они выделены маской `active_artists`. Нулевая
интенсивность слушателя отклоняется, а не заменяется псевдопрослушиванием.

## Поиск и приёмка

Целевая функция — взвешенное среднее квадратов нормированных невязок
`(residual/tolerance)^2`. Случайные целые переносы между двумя ячейками
сохраняют общий объём, неотрицательность и активность всех слушателей.
При заданных `listener_totals` разрешены только переносы внутри столбца.

Улучшения принимаются. Ухудшения принимаются с вероятностью
`exp(-delta_loss/temperature)` при геометрическом изменении температуры.
Асимметричные предложения делают это оптимизационной эвристикой;
стационарное распределение, глобальная сходимость и равномерная выборка
из допустимых матриц не заявляются. Это не стандартный PSO.

Первая матрица, прошедшая **все** допуски, имеет приоритет над матрицей с
меньшей суммарной ошибкой и хотя бы одним FAIL. Поэтому `final_loss`
может быть больше `lowest_loss`; `trace.best_loss` не возрастает, а
`trace.selected_loss` показывает фактически выбранного кандидата.
Если ни одной принятой матрицы нет, сохраняется кандидат с минимальной
целевой функцией и `accepted: false`.

Полный пересчёт каждой характеристики после мутации исключает ситуацию,
когда улучшение одной статистики скрывает ухудшение другой. Ни одна
метрика выплат не входит в демонстрационную целевую функцию: PR/UC
рассчитываются на готовой матрице. При нормировке W=1 каждый пул равен U.

## Происхождение целей и ограничения

В примере семь целей, все предположительные. Никакие данные LFM-1b,
Luminate или коммерческие выплаты в этот пример не подмешаны. Для
эмпирического запуска нужно отдельно определить срез данных и вычислить
нужные характеристики в тех же единицах и на том же уровне агрегации.
Согласовать только средние и медианы недостаточно для выбора закона.

Воспроизводимость проверяется при фиксированных конфигурации и версиях
библиотек. Это плотный малый прототип; масштабирование на миллионы
слушателей не проверялось. Мягкая цель может быть невозможной при жёстких
ограничениях; FAIL после лимита итераций не отличает несовместимость от
неудачного поиска. Для проверки экономических выводов нужны ансамбли
принятых матриц и чувствительность к законам, сеткам, допускам и весам.
