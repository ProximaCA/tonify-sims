#### Pro-rata / user-centric · v0.6 · Tonify Research · 5 сентября 2026

### 1. Содержательная постановка

Первичная задача исследования — получить матрицу прослушиваний, которая
одновременно удовлетворяет заданным ограничениям и статистическим законам.
На каждой принятой матрице сравниваются два способа распределения одной и
той же гарантированной суммы: **pro-rata (PR)** делит общий пул по долям
прослушиваний артистов; **user-centric (UC)** делит кошелёк каждого
слушателя по его собственным прослушиваниям.

PR и UC — альтернативные правила распределения одного бюджета. Прямые
платежи артистам (direct) могут существовать совместно с любым из них;
они не являются третьей взаимоисключающей альтернативой. В первичном
исследовании direct, контрактные слои и сервисные тарифы не моделируются.
Кошелёк означает сумму, уже доступную для распределения после возможной
комиссии при пополнении.

Результат состоит из двух частей: точные арифметические соотношения для
фиксированной матрицы и воспроизводимый генератор матриц с отчётом по
каждому заданному допуску. Совпадение нескольких статистик не доказывает,
что синтетическая матрица воспроизводит реальный рынок. Для такой
интерпретации нужны измеренные цели за согласованный период наблюдения.

### 2. Концептуальная постановка

Артист получает выплату, слушатель предоставляет кошелёк и прослушивания.
Ячейка таблицы относится к одной паре «артист — слушатель» за один общий
период. Её можно измерять количеством прослушиваний или их суммарной
длительностью; смешивать эти единицы в одной матрице нельзя.

Матрица может быть случайным результатом генератора. После её получения
PR и UC вычисляются детерминированно. Все суммы, веса и средние в разделе
3 относятся к конкретной реализации; вероятностная интерпретация весов
для доказательств не нужна. Изменения поведения после смены платёжного
правила не входят в эту постановку.

Веса слушателей в аудитории артиста, её размер и интенсивность — разные
характеристики. Одни и те же распределения суммарных прослушиваний могут
сочетаться с разными связями между артистами и слушателями. Поэтому
генератор должен проверять не только суммы строк и столбцов, но и
структуру ненулевых пар, концентрацию весов и зависимости между
характеристиками аудитории.

Обзор литературы и расширенные результаты предыдущего этапа сохранены
без изменения в [версии v0.5](https://github.com/ProximaCA/tonify-sims/blob/main/paper/THEORY.v0.5.md). Это отложенное приложение,
а не набор предпосылок текущего эксперимента. В этой редакции тождество
PR/UC и неравенство средних используются как арифметические инструменты;
заявка на их научную новизну не делается.

### 3. Математическая постановка

#### 3.1 Таблица обозначений

В таблице собрана нотация; при первом использовании в формулах ниже
обозначения повторно расшифровываются. Сохранены индексы репозитория:
в обозначениях рецензии `a = i`, `l = u`, `A = N`, `L = U`.
Здесь число слушателей — U (в расшифровке L в рецензии опечатка).

| Символ | Определение и область |
|---|---|
| N, i | число артистов и индекс артиста, i ∈ {1, …, N} |
| U, u | число слушателей и индекс слушателя, u ∈ {1, …, U} |
| p, p_iu | неотрицательная матрица N × U; количество или длительность прослушиваний пары |
| P_u | суммарная интенсивность слушателя: Σ_i p_iu > 0 |
| P_i | суммарное прослушивание артиста: Σ_u p_iu ≥ 0 |
| T, P̄ | общий объём прослушиваний T = Σ_u P_u; средняя интенсивность P̄ = T/U |
| A_i, K_u | число слушателей артиста; число артистов у слушателя (числа ненулевых ячеек строки/столбца) |
| W, R | одинаковый положительный нетто-кошелёк; общий пул R = UW |
| W_u | нетто-кошелёк слушателя в отдельно указанном обобщении |
| PR_i, UC_i | выплаты артисту i при соответствующем правиле |
| w^i_u | при P_i > 0: вес слушателя в прослушиваниях артиста, p_iu/P_i |
| m_i, H_i | взвешенное арифметическое и гармоническое средние величин P_u с весами w^i_u |
| CV_i² | при обсуждении спорной оценки: Σ_u w^i_u(P_u−m_i)²/m_i²; конечная взвешенная характеристика |
| c_u | компонент вспомогательного вектора критерия равенства: 1/P_u−U/T |

#### 3.2 Два оператора: определения и краевые случаи

Пусть N — число артистов, U — число слушателей, а p_iu ≥ 0 — прослушивания
артиста i слушателем u за общий период. В матрице p строки соответствуют
артистам, столбцы — слушателям. В старом разреженном экспорте sim4
ориентация обратная: user × artist; для этих формул его транспонируют.

Определим P_u = Σ_i p_iu — интенсивность слушателя u, P_i = Σ_u p_iu —
прослушивания артиста i, T = Σ_u P_u = Σ_i P_i — общий объём и
P̄ = T/U — среднюю интенсивность слушателей. Во всех рассматриваемых
матрицах P_u > 0. Пусть W > 0 — одинаковая доступная к распределению
сумма каждого кошелька, а R = UW — общий пул. Тогда

$$
PR_i = UW\frac{P_i}{T},\qquad
UC_i = W\sum_{u=1}^{U}\frac{p_{iu}}{P_u}.
$$

Здесь PR_i и UC_i — выплаты артисту i при pro-rata и user-centric.
Для фиксированных p и W это детерминированные отображения в вектор
неотрицательных выплат. Если P_i = 0, обе выплаты равны нулю, а их
отношение не определено. Обозначив A_i = #{u : p_iu > 0} — аудиторию
артиста, получаем UC_i ≤ WA_i, поскольку p_iu/P_u ≤ 1.

**Сохранение бюджета — свойство определений.** Непосредственное суммирование
даёт Σ_i PR_i = UW и Σ_i UC_i = WΣ_u(Σ_i p_iu/P_u) = UW.
Следовательно, Σ_i(UC_i−PR_i) = 0. Это не отдельное следствие Теоремы 1.

**Неравные кошельки — обобщение определения.** Если W_u ≥ 0 — доступная
сумма слушателя u и R = Σ_u W_u > 0, то PR_i = RP_i/T и
UC_i = Σ_u W_u p_iu/P_u. Бюджет сохраняется. Нулевой кошелёк допустим,
нулевая интенсивность слушателя по-прежнему исключена. Далее Теорема 1
сначала формулируется для одинакового W.

#### 3.3 Предпосылки первичного исследования

- **A1 (активные слушатели и единицы).** Каждый включённый кошелёк имеет
  P_u > 0. В целочисленном прототипе p_iu ∈ ℤ₊, поэтому P_u ≥ 1;
  отдельное прежнее A3 объединено с A1. Для длительностей допускаются
  неотрицательные вещественные ячейки и те же формулы. Порог активности,
  «silent payer / deaf listener» и передача его денег сервису сейчас не
  моделируются. При расширении одно правило исключения следует явно
  задать для обоих бюджетов.
- **A2 (одинаковые нетто-кошельки в основном сравнении).** W одинаков для
  всех слушателей. Набор различных W_u допустим по §3.2, но тогда простое
  условие через H_i из Теоремы 1 заменяется общей формулой ниже. Убывающая
  комиссия и уровни подписок, включая суперфанатскую, оставлены для
  последующего этапа.

Прежние **A4 и A7** не выделяются как допущения: детерминированный закон
выплат на одной реализации матрицы уже задан в §3.2. Прежнее **A5**
относилось к direct и отложено. Сервисную комиссию считаем уже вычтенной
из кошельков. Прежнее **A6** в исходнике означало контрактный проход — это
другой слой, его также не вводим в текущую модель.

Прежнее **A8** не навязывает генератору конкретный хвост: семейство закона,
его параметры, область действия и статус задаются на входе. Нормальный,
логнормальный, Pareto- и beta-законы — кандидаты для подходящих статистик,
а не установленные универсальные законы музыкального рынка.

Прежнее **условие (C)** относится только к отложенной хвостовой лемме L3
в [v0.5, §3.4.3](https://github.com/ProximaCA/tonify-sims/blob/main/paper/THEORY.v0.5.md). Оно является условием того утверждения,
а не концептуальной гипотезой и не требованием к текущему генератору.

#### 3.4 Арифметические утверждения для одной матрицы

##### 3.4.1 L1: тождество отношения и условия выигрыша UC

**Зачем это.** Для принятой матрицы можно точно определить, какие артисты
получат больше при смене PR на UC. Вес каждого слушателя в таком расчёте
равен его доле в прослушиваниях данного артиста; обычное среднее по людям
этот расчёт не заменяет.

**Теорема 1.** При A1–A2 для артиста i с P_i > 0 определим
w^i_u = p_iu/P_i — нормированные неотрицательные веса (Σ_u w^i_u = 1),
m_i = Σ_u w^i_u P_u — взвешенное арифметическое среднее интенсивности и
H_i = (Σ_u w^i_u/P_u)⁻¹ — её взвешенное гармоническое среднее. Тогда

$$
\frac{UC_i}{PR_i}
=\bar P\sum_u\frac{w^i_u}{P_u}
=\frac{\bar P}{H_i}
=\frac{\bar P}{m_i}\frac{m_i}{H_i}.
$$

*Доказательство.* Делим WΣ_u p_iu/P_u на UWP_i/T, сокращаем W и P_i,
получаем (T/U)Σ_u(p_iu/P_i)/P_u. Подстановка определений даёт все три
равенства. Это конечные суммы, без перехода к случайным величинам. ∎

**Неравенство средних и достаточное условие.** Неравенство Коши–Буняковского
для √(w^i_uP_u) и √(w^i_u/P_u) даёт
(Σ_u w^i_uP_u)(Σ_u w^i_u/P_u) ≥ (Σ_u w^i_u)² = 1. Поэтому

$$
H_i\le m_i,\qquad
\frac{UC_i}{PR_i}\ge\frac{\bar P}{m_i}.
$$

Равенство H_i = m_i имеет место тогда и только тогда, когда P_u постоянно
на носителе весов, то есть среди слушателей с p_iu > 0.
Достаточное условие неуменьшения выплаты: m_i ≤ P̄; при m_i < P̄
выигрыш строгий. Для проверки этой достаточности нужна **верхняя** оценка
m_i. Например, max_{u:p_iu>0} P_u ≤ P̄ достаточно. Нижняя оценка m_i сама
по себе такого вывода не даёт.

**(a) Точный критерий равенства.** Для данного артиста UC_i = PR_i
эквивалентно Σ_u p_iu(1/P_u−U/T) = 0. Для всех артистов одновременно это
p c = 0, где c — вектор с компонентами c_u = 1/P_u−U/T, то есть c лежит
в ядре p. Условие P_u ≡ P̄ достаточно, но не необходимо: один артист и
два слушателя с p = (10, 20) дают UC_1 = PR_1 = 2W.

**(c) Необходимое и достаточное условие неуменьшения.**
UC_i ≥ PR_i ⇔ H_i ≤ P̄; строгое преимущество эквивалентно H_i < P̄.
Условие m_i ≤ P̄ только достаточно. Буквы (a) и (c) сохранены для
сопоставления с рецензией; прежний пункт (b) перенесён к определениям.

**(d) Граница интерпретации неоднородности.** При m_i = P̄ имеем
UC_i/PR_i = m_i/H_i ≥ 1, со строгим неравенством при неодинаковых P_u
на носителе весов. Это утверждение о данной взвешенной последовательности.
Изменение матрицы меняет одновременно веса, средние и общий объём;
монотонного закона «рост дисперсии всегда увеличивает доход UC» отсюда
не следует. Предыдущее название «премия за дисперсию» снято.

**Проверка оценки с коэффициентом вариации из рецензии.** При обычном
определении CV_i² = Σ_u w^i_u(P_u−m_i)²/m_i² неравенство
m_i/H_i ≥ 1+CV_i² неверно в общем случае. Возьмём

$$
p=\begin{pmatrix}9&1\\1&99\end{pmatrix}.
$$

Для первого артиста P_u = (10, 100), w^1 = (0.9, 0.1), m_1 = 19,
H_1 = 1000/91. Поэтому m_1/H_1 = 1.729, тогда как
1+CV_1² = 1090/361 ≈ 3.01939. В рецензии формула CV не задана; этот
контрпример относится к явно выписанному здесь стандартному определению.
Корректное точное выражение для разрыва средних:

$$
\frac{m_i}{H_i}-1
=\sum_u w^i_u\frac{(P_u-m_i)^2}{m_iP_u}\ge0.
$$

Оно получается раскрытием квадрата и использует другие знаменатели,
чем CV_i². Для достаточного условия выигрыша усиление через CV не нужно.

**Что это значит.** Точное сравнение требует всей матрицы или вычисленных
из неё взвешенных средних аудитории. Нишевость, число слушателей или
неоднородность сами по себе не определяют победителя. Для каждой принятой
матрицы рассчитываются оба правила и проверяется общий бюджет; направление
перераспределения не закладывается в цель генератора.

**Неравные кошельки.** С определениями §3.2 получаем
UC_i/PR_i = (T/R)Σ_u w^i_u W_u/P_u. Формула остаётся конечной суммой,
но критерий H_i ≤ P̄ без учёта W_u к ней неприменим.



### 4. Генерация матрицы по ограничениям и статистическим законам

#### 4.1 Входы и проверяемые характеристики

Новый отдельный прототип — [sim4/constrained_gen.py](https://github.com/ProximaCA/tonify-sims/blob/main/sim4/constrained_gen.py).
Существующие сценарии sim1–sim6 не изменены. На вход передаются N и U,
общее целое число прослушиваний T ≥ U, общий период, seed, число итераций,
параметры поиска и список статистических целей. Дополнительно можно
зафиксировать весь вектор P_u, сумма которого должна равняться T.

**Жёсткие ограничения:** p_iu ∈ ℤ₊, Σ_iu p_iu = T, P_u ≥ 1; при заданном
векторе P_u каждая сумма столбца сохраняется точно. Конфигурация с T < U
или несовпадающей суммой заданных P_u отклоняется до поиска. Вещественные
длительности поддержаны формулами выплат, но не этим целочисленным
оптимизатором.

**Статистические цели:** для распределения задаются семейство функции
распределения, его параметры, фиксированная сетка сравнения и допустимая
невязка; для скалярной характеристики — целевое значение и допуск. Каждая
цель имеет отдельный положительный вес, статус `measured / assumed / derived`
и описание происхождения. Реализованы следующие характеристики:

| Характеристика | Что именно сравнивается |
|---|---|
| `listener_totals`, `artist_totals` | P_u по всем слушателям; P_i по всем артистам, включая нулевых |
| `listener_degrees`, `artist_audiences` | K_u — число артистов слушателя; A_i — число слушателей артиста |
| `positive_plays` | положительные p_iu по всем активным парам |
| `artist_weights` | положительные w^i_u, объединённые по активным парам; это не одинаковый закон для каждого артиста |
| `artist_weight_hhi` | Σ_u(w^i_u)² по артистам с P_i > 0; концентрация вклада слушателей |
| `listener_share_hhi` | Σ_i(p_iu/P_u)² по слушателям; концентрация его предпочтений |
| `weighted_intensity`, `harmonic_intensity` | m_i и H_i по артистам с P_i > 0 |
| `zero_fraction` | доля нулевых ячеек |
| `artist_top_share` | доля всех прослушиваний у ⌈fN⌉ крупнейших по P_i артистов; f ∈ (0,1] задано |
| `artist_gini` | коэффициент Джини сумм P_i, включая артистов с нулевыми суммами |
| `activity_audience_correlation` | корреляция log A_i и log(P_i/A_i) по активным артистам; при постоянной переменной не определена и не проходит допуск |

Параметры normal/lognormal: `mu`, `sigma` (у lognormal — параметры
логарифма); Pareto: `shape`, `scale`; beta: `alpha`, `beta` на [0,1].
При необходимости закон сначала усекается на `lower < x ≤ upper`, затем
`ceil: true` задаёт округление вверх. Для целого порога x функция
распределения округлённого значения равна исходной функции в floor(x).
Поддержка закона должна соответствовать области выбранной характеристики.

#### 4.2 Многокритериальная задача и алгоритм

Пусть j — индекс статистической цели, Z_j(p) — конечная последовательность
значений её характеристики, F_j — заданная функция распределения, а G_j —
фиксированная сетка порогов. Эмпирическая функция
F̂_j(x;p) = #{z ∈ Z_j(p): z ≤ x}/|Z_j(p)|. Невязка распределения:

$$
r_j(p)=\max_{x\in G_j}|\widehat F_j(x;p)-F_j(x)|.
$$

Для скалярной цели z_j с заданным значением z_j* невязка равна
r_j(p) = |z_j(p)−z_j*|. При допуске ε_j > 0 и весе λ_j > 0
поиск уменьшает скаляризацию

$$
J(p)=\frac{\sum_j\lambda_j(r_j(p)/\varepsilon_j)^2}{\sum_j\lambda_j}.
$$

Низкое J не заменяет покомпонентную приёмку: **каждое** r_j ≤ ε_j
и все жёсткие ограничения обязательны. Невязка по сетке — не супремум по
всей числовой оси и не статистический тест с p-value. Зависимые ячейки и
подбор самой матрицы под цели не дают основания применять стандартную
интерпретацию KS-теста; [документация SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.kstest.html)
также ограничивает его стандартную применимость непрерывными распределениями.

**Метод поиска.** Начальная матрица распределяет T целых прослушиваний
случайно, оставляя каждому слушателю хотя бы одно. На шаге выбираются две
ячейки; из первой во вторую переносятся целые прослушивания. Донор не
становится отрицательным, последний плэй столбца не переносится в другой
столбец. При фиксированных P_u разрешены только переносы внутри столбца.
Улучшения J принимаются; ухудшения — с вероятностью
exp(−ΔJ/θ_t), где ΔJ — рост целевой функции, θ_t > 0 — убывающая
температура. Это стохастический поиск с правилом приёма отжига; при
асимметричных переносах он не заявляется как сэмплер заданного распределения.

Поиск останавливается на первой матрице, прошедшей все допуски. Она
имеет приоритет над меньшим J у матрицы с одним проваленным допуском.
Если лимит итераций исчерпан, возвращается кандидат с минимальным
достигнутым J и явный статус `accepted: false`. История хранит отдельно
минимальное достигнутое J и J выбранного кандидата. Неудача поиска не
доказывает несовместимость целей; успех не доказывает глобальный оптимум.

**Почему не названо PSO.** В стандартном [PSO Kennedy–Eberhart](https://staff.washington.edu/paymana/swarm/kennedy95-ijcnn.pdf)
частица представляет целый кандидат решения, её координаты — переменные
задачи. Для прямого применения здесь частицей была бы матрица, а не одна
ячейка. Идея «частица = ячейка» требует отдельно задать совместную целевую
функцию и правила взаимодействия. Предложенная рецензией возможность
аналогичного стохастического алгоритма реализована переносами; сравнение
с полноценным роем остаётся отдельным экспериментом.

#### 4.3 Выбор законов и эмпирическая калибровка

Количество целей само по себе не обеспечивает реализм. Необходимы
согласованные единицы, период, уровень агрегации и область применения
каждого закона. Сумма P_i обязана совпадать с суммой P_u, сумма A_i —
с суммой K_u; также A_i ≤ min(U,P_i), K_u ≤ min(N,P_u) для целых плэев.
Эти связи следуют из матрицы, поэтому произвольные независимые целевые
законы могут оказаться несовместимыми.

В [LFM-1b, Schedl 2016, таблица 6](https://www.cp.jku.at/people/schedl/Research/Publications/pdf/schedl_icmr_2016.pdf)
21.21 и 5.16 — характеристики распределения **среднего числа плэев на
артиста у пользователя**: среднее и медиана пользовательских средних.
Они не задают среднее и медиану объединённой выборки положительных p_iu,
не доказывают её логнормальность и не относятся автоматически к одному
году. Поэтому прежняя подгонка закона ячейки из этой пары чисел не
переносится в новый генератор как эмпирический закон. Доли треков из
Luminate также не переносятся на артистов без отдельной модели агрегации.

Существующие [emp1/SPEC.md](https://github.com/ProximaCA/tonify-sims/blob/main/emp1/SPEC.md) и [emp1/README.md](https://github.com/ProximaCA/tonify-sims/blob/main/emp1/README.md)
описывают измерение связей аудитории и активности на Last.fm. Их
редуцированный наклон не равен корреляции из таблицы §4.1: подставлять
одно число вместо другого нельзя. Для калибровки каждой новой цели
нужно вычислить именно её статистику на выбранном срезе исходных данных.

Включённый пример полностью `assumed`: это проверка работоспособности
метода. Полная CDF по каждому артисту, зависимости высших порядков и
временная структура в прототипе не заданы. Прохождение маргинальных
ограничений не определяет эти свойства однозначно.

#### 4.4 Проверки и воспроизводимость

Из корня репозитория:

```bash
python3 -m unittest sim4.test_constrained_gen -v
python3 sim4/constrained_gen.py --config sim4/constrained_example.json --output work/constrained-demo
```

Выходы: `matrix.csv` (артисты × слушатели), `payouts.csv` (PR, UC,
отношение и взвешенные средние каждого артиста при W=1) и `report.json` с точной
конфигурацией, версиями NumPy/SciPy, seed, SHA-256 матрицы, начальными и
конечными невязками, историей поиска и отдельными воротами PR/UC.
Код выхода 0 означает прохождение всех допусков; код 1 — сохранённый,
но не принятый кандидат. Ошибка конфигурации даёт код 2.

Тесты проверяют тождество отношения, сохранение бюджета, неравенство
средних, точную формулу их разрыва, ядровой критерий, контрпример к CV,
нулевых артистов, вещественные длительности, неравные кошельки,
повторяемость seed, сохранение фиксированных сумм, обработку повторов в
CDF и отказ при недостижимой цели. Численные тесты дополняют доказательства
§3.4, а не заменяют их.

Пример seed=42: N=12, U=48, T=1200; все семь целей прошли допуски
после 4080 предложений мутаций (1222 приняты). J снизилось с 46.661859
до 0.532441. Максимальная ошибка UC_i/PR_i = P̄/H_i составила

**Ограничения реализации.** Плотная матрица и полный пересчёт характеристик
после каждого предложения рассчитаны на малые методологические опыты.
Масштаб прежнего sim4 не проверялся. Прототип не выдаёт равномерную
выборку из множества допустимых матриц и не доказывает соответствие
заданному совместному вероятностному закону. Для оценки устойчивости
экономических выводов нужны несколько принятых матриц, разные стартовые
условия и анализ чувствительности к целям и допускам.
