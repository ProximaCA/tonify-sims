# Публикация сайта на GitBook

Репозиторий — источник истины. GitBook только рендерит. Никакого редактирования
в вебе: правка идёт в репо → PR → синк.

## Как это устроено

```
docs/
  facts.py        66 фактов как пары (файл-источник, регулярка). Единственный мост
                  между репозиторием и сайтом. Факт не извлёкся → сборка падает.
  build.py        шаблоны + факты → готовые страницы. --check сверяет, что
                  закоммиченные страницы = результат сборки.
  gates.py        ворота приёмки G1–G3 (+G2.4 по сети). FAIL = не публикуем.
  _templates/     ИСХОДНИКИ. Правки вносить сюда.
  en/  ru/        СБОРКА. Правки руками сюда бессмысленны — затрутся.
  g4-cold-reader.md  эталон и протокол теста холодного читателя.
```

Цифру на странице набрать руками нельзя: G1.1 находит любое число, которого
нет ни в фактах, ни в белом списке (годы, библиография чужих работ). Правка
любого текста:

```bash
# 1. правим docs/_templates/<lang>/...
python3 docs/build.py       # пересобрать
python3 docs/gates.py --net # ворота
```

Синк подключён к **корню репозитория**, поэтому корень пространства
переставляет корневой `/.gitbook.yaml` (`root: ./docs/en/`). Без него GitBook
тянет в сайт README, CHANGELOG и исходники симуляций. Файлы
`docs/en/.gitbook.yaml` и `docs/ru/.gitbook.yaml` — на случай, если директорию
синка укажут явно; тогда используются они, результат тот же.

Веб-редактирование выключено в обоих пространствах (`editMode: locked`) — это
G5 в предпочтительном виде: расходиться репозиторию и сайту нечем.

## Единственная незакрытая механика: автосинк русского

Английское пространство обновляется само на каждый push. Русское наполнено
разовым импортом через API (`POST /spaces/<id>/git/import` с
`repoProjectDirectory: docs/ru`) — постоянного вебхука у него нет, потому что
API отдаёт конфигурацию Git Sync только на чтение.

Пока это не исправлено, после каждого push русские страницы обновляются
повторным импортом. Чтобы закрыть насовсем: настройки пространства `Русский`
→ Git Sync → GitHub → `ProximaCA/tonify-sims`, ветка `main`, директория
`docs/ru`. После этого правка в репозитории доезжает в оба языка сама.

## Остальное, что делается только руками

1. **Домен.** Settings → Domain. Пока сайт живёт на выданном
   `tonify-1.gitbook.io/tonify-docs`; ссылки в `README.md` и `README.ru.md`
   ведут туда и потребуют правки при смене домена.

2. **Глоссарий.** Страница `GLOSSARY.md` синкается как обычная; автоподсветку
   терминов включает GitBook (Settings → Glossary для пространства), после чего
   термины подсвечиваются в тексте с всплывающей подсказкой.

3. **Пустой вариант.** `sitesp_2p0bl` скрыт, но существует. Удаление —
   деструктивная операция, через API недоступна.

**Create translation не использовать.** Это AI-перевод из английского
пространства: русский текст сгенерирует GitBook, и он разойдётся с
репозиторием. Русские страницы собираются из русских источников
(`paper/THEORY.md`, `SOURCES.ru.md`) и синкаются как обычный контент.
Вдобавок GitBook AI в организации отключён, так что перевод и не запустится.

## Проверка после синка (G5) — пройдена 2026-08-17

- Публичный сайт отвечает 200 на `/`, `/en`, `/ru` и на вложенных страницах
  обоих языков; числа приходят в HTML (`+0.101`, `75%`), переключатель языков
  в шапке.
- Английское пространство содержит только страницы `docs/en` — README,
  CHANGELOG и исходники симуляций в сайт не попали.
- Веб-редактирование выключено в обоих пространствах, поэтому вторая половина
  G5 (правка в вебе доезжает до репозитория) неприменима по построению: репо
  единственный источник.
