# ТЗ для Claude Code: tonify-sims (симуляции 2 и 3)

## Контекст
Tonify — прямая музыкальная экономика в Telegram (донаты вместо котла). Симуляция 1 (касса)
готова: `sim1/tonify_cash_sim.py` + paper/RESULTS.md рядом — прочитай их первыми, там мир, якоря и стиль.
Твоя задача: собрать симуляции 2 и 3 в публичный репозиторий `tonify-sims`.

## Общие требования
Python, numpy/networkx/matplotlib, seed=42, тёмная палитра из sim1 (#0D0A1A фон, #6B2FFF/#00D4F5/#FF4D8D).
Каждая симуляция: свой .py, README с параметрами→источниками, валидационный блок ПЕРЕД выводами,
секция «Честные ограничения». Никаких выводов без фальсификатора.

## SIM 2 — распространение музыки по социальному графу Telegram
Граф: Barabási–Albert (m=3, N=50k) + плантированные клики размером 5–40 (чаты; лог-нормальное
распределение размеров) поверх; хабы = топ-узлы по степени (каналы).
Механика заражения: COMPLEX CONTAGION (Centola) — узел принимает трек при k≥2 независимых
касаниях от разных соседей (для сравнения прогнать и simple contagion k=1). Внутри клики
одно сообщение = касание всем участникам одновременно (широкий мост).
Эксперименты:
  A. Посев: random vs топ-хабы vs случайные клики — охват на 1 посев при равном бюджете.
  B. Фазовая диаграмма K: измерить эффективный branching factor; показать суб/крит/сверхкритику.
  C. Simple vs complex: где ломается «теория рукопожатий» (длинные слабые связи не проводят complex).
Выходы: reach-per-seed кривые, фазовая диаграмма, gif одного каскада.
Фальсификатор GTM: если при complex contagion посев в хабы НЕ бьёт случайный при равном бюджете —
гипотеза хабов Tonify неверна, так и написать.

## SIM 3 — анти-кладбище (агентная токеномика)
Агенты: юзеры (приток/отток), артисты, спекулянты. Два режима казны:
  A. «Закон Tonify»: выплаты_t ≤ внешний_приток_t (кэшбэк, не эмиссия).
  B. STEPN/Axie-режим: выплаты из эмиссии, доходность зависит от притока новых.
Калибровка формы коллапса B: Hamster 300M→12M за 6 месяцев (AInvest; CryptoPotato, сент. 2024).
Выходы: траектории казны и DAU обоих режимов на 36 мес; распределение даты смерти режима B
по 200 прогонам; один слайд-график «две кривые».
Фальсификатор: если режим A тоже умирает при нулевом росте — найти при каком оттоке и честно показать.

## Агентная структура (как делать структурно — команда субагентов Claude Code)
Роли и цикл на каждую задачу: **economist** (спека модели, параметры→источники из PAPER/README)
→ **engineer** (реализация, seed=42, тесты на валидационных мишенях T1–T3) → **red-team critic**
(жанр CRITIC.md: обвинение→вердикт→действие; право отзывать числа) → **viz** (палитра #0D0A1A/#6B2FFF,
подпись «аналитика vs симуляция» на каждой фигуре; после генерации каждой фигуры — проверка
соответствия легенды и подписи фактическому направлению шкалы) → economist принимает.
Правило матрицы (обязательное): каждый механизм выплат моделируется в ОБЕИХ колонках
{signed (лейбл-проход 6,8% / 360-сделка 70%), independent} — см. fig7 и Addendum v0.5.
Ни один вывод не мёржится без фальсификатора. Итог каждой сессии — обновление paper/PAPER.md.
